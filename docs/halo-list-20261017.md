# Halo List: pet program design (v0.1 draft)

*Pet program #16 · icon **VSCode Angel** · repo `findastra/vscode-angel` · drafted 2026-10-17 by Claude Haiku 5.5 (`claude-haiku-5-5`) for Astra.*

**Status: design only. Nothing in this document is built.** The offline record app in `vscode-angel` is the start of the Notes tool and worklist. The tools below are planned.

## Purpose (one sentence)

Open any pet program, tool or trick in VS Code, so that its owner understands what the code does, and never has to trust code they cannot read.

Every tool below serves that purpose. A tool that does not help someone understand their code does not belong in this program.

## What a person can do with it

1. Pick a project, a pet program, a tool or a trick, and **open it in VS Code**.
2. Get an **initial assessment**: how vibe-coded it looks, the errors it has, and a suggested structure.
3. Get **plain Markdown explanations** (`##` headings, one file each): what it is, what it does, what it reads and writes, what depends on it, and what could go wrong.
4. **Update it step by step** with the AI built into VS Code. Each change is shown as a diff, approved by the owner, and written up in Markdown.

Steps 2 to 4 always end with a note in the project's `docs/understanding/` folder, so the next person (or assistant) starts from the notes, not from guesswork.

- **Un-vibe a project:** run the initial assessment, then the explainer, then propose a structure. Stop at each gate for the owner to say yes.
- **Explain a single file:** the explainer on one file only, then ask whether to add it to the notes.

## How the vibe rating works (the L2 tool)

The rating is a **checklist with visible numbers**, not an AI judgment, so the owner can check every point. Each finding names the file and the line.

| Check | Why it matters |
|---|---|
| Files with no explanation (no header comment, no README entry) | Nobody can say what they are for. |
| Functions longer than about 80 lines | Hard to read and to test. |
| Same block of code repeated in 3 or more places | A fix in one place is missed in the others. |
| Code that nothing calls | Dead weight that still gets read. |
| Hard-coded secrets, keys or personal paths | A security risk. Also reported to Pet Police Officer's watch. |
| No tests, or tests that never run | No way to know it still works. |
| Errors the editor already reports (VS Code's own diagnostics) | Real bugs the owner can see. |
| Missing error handling around file, network or user input | Crashes that look like "random" failures. |

The rating is a percentage of checks passed, reported with the list. It is labelled **an estimate of readability and risk**, never a score of the author. Limit: it cannot tell whether the code does what the owner wants. Only the owner can say that.

## Suggested structure (the L2 tool, part of the assessment)

The assessment proposes a folder layout from what it finds, for example:

```
src/        the code that runs
tests/      checks that prove it works
docs/
  understanding/   one Markdown file per module: what it is, does, needs
  changes/         one Markdown note per update, dated
README.md   what the project is, how to run it, its limits
```

It never moves a file by itself. It writes the proposal as a Markdown plan; the owner approves each move.

## Data

- Explanations, notes and assessments are files **in the project's own `docs/` folder**, so they travel with the code.
- Nothing is stored on a server. The program keeps only its own settings (which folders are granted) in `%LOCALAPPDATA%\astras-pet-os\halo-list\`, per the framework.
- Code leaves the PC only when the explainer or guided update asks the AI in VS Code. That is an L4 decision, not a default: **private projects (health, finance, personal) use a local model or are not explained.**

## Security and rings

- Everything the program does runs inside the project folder granted to it. It has no grant to the whole PC.
- The two AI tools need a short-lived key from Iron Gates. Every write is reported to Pet Police Officer.
- The program never edits a file without an approved diff, and never runs a command the owner has not seen.
- Shared-tool rule: `open-in-vscode` is one copy, owned by Halo List. Other pets (for example, File Master for its scripts) get a grant, never their own copy.

## Mood map (the nine moods, as the framework says)

- **Asleep (9):** no project granted yet.
- **Calm (1):** nothing needs the owner.
- **Worried (5):** the assessment found errors or risks to look at.
- **Sick (7):** only the owner can unblock it: a missing grant, a missing VS Code, a missing AI account.
- **Happy (3):** the last explanation or update was finished and approved.

The mood reports the program's real state. It is never a display choice.
