# Pet coin proposal — 2026-10-14

Status: proposed implementation approach; owner requested appearance and first implementation for Chip. OpenAI Codex (GPT-6).

## Decision

Reuse approved artwork on both faces of a spinning coin. Interpret thickness as 5% of diameter. Use a glossy gold edge without sparkle particles. Each Pet Program places its own clickable coin bottom-right, opening Astra's Cyber Deck — [Pet name] Chat. Chip keeps original Data Dealer face artwork and adopts the shared chat panel.

Use lightweight CSS 3D layers for one program launcher, with a shared asset/proportion specification. Use actual cylinder geometry in the existing Three.js System Map for close-up 3D viewing. These are two rendering adapters for the same visual contract, not two independently maintained sets of artwork. Keep face images correctly oriented on the back. A 4-second rotation is an initial adjustable proposal, not an approved final speed.

## Hosting and evidence

Keep public dated PNG/WebP/SVG assets and shared code in the existing GitHub Pages deployment. No new account, storage provider or per-pet GIF/video is necessary. Preserve individual pet repo art copies/provenance and canonical asset mapping. Public Goldfish art URL https://findastra.github.io/astras-pet-os/art/icons/github-goldfish-20261012.png returned HTTP 200 on 2026-10-14; this does not verify every pet URL.

Current local art/icons contains 44 PNGs, all 96x96. The map generator embeds images for standalone viewing. makeIcon currently draws into a 128x128 canvas, and icons are flat Three.js Sprites. Three.js r128 already provides the map renderer. Coins and high-resolution zoom are not yet implemented there.

Keep the largest approved master; use 1024px or larger faces when real source detail supports that. SVG is appropriate only for genuinely vector art; do not auto-trace or regenerate approved art just to meet a nominal size. Preserve pixel art with intentional nearest-neighbor filtering. Remove forced texture downsampling, lazy-load large face assets near the selected coin, and adjust focus/near-plane/zoom limits without destabilizing the map.

## Alternatives and tradeoffs

- Animated GIF/video: simple embedding, but fixed resolution, duplicated exports, weak zoom, and limited interactive control. Not recommended.
- CSS coin everywhere: lightweight for page buttons, but does not integrate cleanly with map depth and picking. Use only for launchers.
- Three.js everywhere: consistent true geometry, but unnecessarily adds a WebGL renderer to every otherwise lightweight Pet Program. Reuse existing map renderer only initially.

## Acceptance

Flash Audit A44-A49 covers appearance, click targets, chat, hosting, zoom, motion/performance and truthful implementation status. Provide reduced-motion/static fallback and pause control. Do not add flashing or sparkles. Freeze/pause offscreen or hidden coins. Test hide/unhide cycles for animation-loop and GPU-resource leaks.
